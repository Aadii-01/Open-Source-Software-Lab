# Open Source Definition (OSD) - The 10 Principles
These are the principles maintained by the Open Source Initiative. These principles determine whether a software license can officially be called an Open Source License

## What is the Open Source Definition (OSD)?
The OSD is the official set of the criteria maintained by the Open Source Initiative (OSI) that determines whether a software license can be called an Open Source License
Software license -> Open source considered -> if it satisfies all the principles defined by OSI
Just publishing source code does not make software open source
The license must satisfy the Open Source Definition

## Why was the OSD created?
When Open Source became popular in the late 1990s, companies started using terms like:
- Shared Source
- Source Available
- Community Source
Many of these licenses restricted users
This created confusion
The OSI introduced the ODS to establish one internationally accepted standard for open-source licenses
Today license such as: MIT, Apache 2.0, BSD, GPL, LGPL, MPL
are recognised as opensource because they satisfy the OSD

## Latest Status
The Open Source Definition is still maintained by the Open Source Initiative (OSI).

Although the wording has remained stable for many years, the OSD is actively applied to evaluate modern licenses, especially for areas like cloud computing and AI-related software.

Recent discussions often involve whether newer "source-available" AI licenses qualify as open source. Many do not, because they impose additional restrictions that violate the OSD.

This is why terms like "open-weight AI models" and "source-available AI" are increasingly used instead of calling everything "open source."


## The 10 principles of the OSD
1. **Principle 1**: Free Redistribution
The license must allow anyone to sell or give away the software without paying royalties
<br>
Meaning we can share it, sell it, redistribute it without asking permission from the orginal developer
<br>
Example: Ubuntu Linux - Anyone can download it, copy, share it and sell DVDs containing it provided they follow the license
<br>
Q. Why is it important?
-> Without the freedom, software could'nt spread through the community

2. **Principle 2**: Source Code
<br>
The software must include source code or provide an easy way to obtain it.
Binary-only distribution is not enough.
<br>
Example:
Python
<br>You can download:
- Source code
- Documentation
- Release history
from its official repositories.
So that, developers cannot study or improve software without the source code.

3. **Principle 3**: Derived Works
The license must allow people to:
- Modify software
- Improve software
- Create new software based on it<br>
These are called derived works.<br>
Example:
Android is derived from the Linux kernel.
Ubuntu is derived from Debian.
Linux Mint is derived from Ubuntu.

4. **Principle 4**: Integrity of the Author's Source Code
This principle allows a license to protect the author's reputation without preventing modification.<br>
For example, a license may require modified versions to:
- Be clearly marked as modified.
- Use a different name if appropriate.<br>
Example:
Many Linux distributions modify upstream software while clearly identifying their changes.

5. **Principle 5**: No Discrimination Against Persons or Groups<br>
A license cannot restrict software based on:
- Nationality
- Gender
- Religion
- Organization
- Company
- Individual<br>
Everyone must receive the same rights.<br>
Example:
A license cannot say:
"Only students may use this software."
or
"Company XYZ cannot use this software."
Both would violate the OSD.

6. **Principle 6**: No Discrimination Against Fields of Endeavor<br>
Software must be usable in any field.
Examples:
- Education
- Healthcare
- Artificial Intelligence
- Government
- Military
- Commercial business
- Scientific research<br>
Invalid Example:
"This software cannot be used for commercial purposes."
Such a restriction means the license is not open source.

7. **Principle 7**: Distribution of License<br>
The rights granted by the license must automatically apply to everyone who receives the software.<br>
Users should not have to:
- Sign new agreements
- Request additional permission
- Register before using the software<br>
Example:
When you clone a GitHub project under the MIT License, you automatically receive the rights granted by that license.

8. **Principle 8**: License Must Not Be Specific to a Product<br>
The rights must not depend on the software being distributed as part of a particular product.<br>
Example:
If software is removed from a Linux distribution, the same license must still apply.<br>
The license cannot become invalid simply because the distribution method changed.

9. **Principle 9**: License Must Not Restrict Other Software<br>
An open-source license cannot require that all software distributed alongside it also be open source.<br>
This principle ensures different licensed software can coexist.<br>
Example:
You can distribute MIT-licensed software on the same storage medium as proprietary software.<br>
The MIT license doesn't force unrelated software to become open source.

10. **Principle 10**: Technology Neutral
A license must not depend on:
- A specific programming language
- A specific operating system
- A specific interface
- A specific technology<br>
The license should remain valid regardless of technological changes.<br>
Example:
A license cannot state:
"This software may only be used on Linux."
That would violate the OSD.

| 1   | Free Redistribution               | Freely share or sell the software                   |
| 2   | Source Code                       | Source code must be available                       |

| 4   | Integrity of Author's Code        | Protect author attribution while permitting changes |
| 5   | No Discrimination Against Persons | Equal rights for everyone                           |
| 6   | No Discrimination Against Fields  | Allow use in any domain                             |
